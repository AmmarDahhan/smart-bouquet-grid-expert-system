# روبوت توزيع الباقات – معرض الورود الذكي

## وصف المشروع

هذا المشروع يقدّم حلًا لمسألة **بحث قائم على القواعد** باستخدام **Experta**، حيث يتحرك روبوت داخل شبكة (Grid) ليأخذ الباقات من المستودع ويُسلّمها إلى الأجنحة حسب الاحتياجات المطلوبة، مع احترام القيود الخاصة بالحركة والحمولة والتحميل والتفريغ.

الفكرة الأساسية ليست كتابة بحث تقليدي بأسلوب `generate next state`، بل بناء **قاعدة معرفة** تتفاعل مع **حقائق** تمثل الحالة الحالية، وتنتج حقائق جديدة أو تعدّلها أو تحذفها حتى نصل إلى الحالة الهدف.

---

## الهدف من الوظيفة

الهدف هو إيجاد **أقل تكلفة ممكنة** لإيصال الباقات المطلوبة إلى جميع الأجنحة، بحيث تكون الكلفة الإجمالية ناتجة عن:

- كل حركة = 1
- كل عملية تحميل = 1
- كل عملية تفريغ = 1

وتكون الحالة النهائية صحيحة عندما:

- جميع الأجنحة استلمت احتياجاتها كاملة
- الروبوت لا يحمل أي باقات

---

## مكوّنات المسألة

### 1) الشبكة (Grid)

المعرض ممثل على شكل شبكة ثنائية الأبعاد بحجم متغير.

### 2) المستودع (Warehouse)

مكان ثابت داخل الشبكة تُخزَّن فيه جميع الباقات.

### 3) الروبوت (Robot)

يبدأ من موقع محدد داخل الشبكة، ويمكنه التحرك فقط في أربعة اتجاهات:

- يمين
- يسار
- أعلى
- أسفل

### 4) الأجنحة (Pavilions)

كل جناح له:

- اسم
- نوع ورد محدد
- موقع داخل الشبكة
- احتياجات من الألوان

### 5) الباقات (Bouquets)

كل باقة تمثل:

- نوع الوردة
- اللون
- العدد

## وظيفة كل ملف

### `models.py`

يحتوي على تعريفات البيانات الأساسية:

- الروبوت
- الجناح
- الباقة
- الحالة الكاملة

### `knowledge_base.py`

يحتوي على البيانات الثابتة الخاصة بالمشكلة:

- أبعاد الشبكة
- موقع المستودع
- موقع البداية للروبوت
- تعريف الأجنحة واحتياجاتها
- تحديد الحمولة القصوى
- الحالة الابتدائية

### `rules.py`

يحتوي على قواعد النظام الخبير:

- قواعد الحركة
- قاعدة التحميل
- قاعدة التفريغ
- قواعد منع انتهاك القيود
- قواعد الوصول للحالة الهدف
- قواعد تتبع المسار

### `heuristic.py`

يحتوي على دالة التقدير `h(n)` المستخدمة في A\*.

### `search.py`

يحتوي على منطق البحث وإدارة الحالات:

- توليد الحالات
- تتبع الحالات الزارعة
- اكتشاف الحالة الهدف
- طباعة الحل
- طباعة شجرة البحث

### `main.py`

الملف التنفيذي الرئيسي لتشغيل المشروع وتجربة المثال.

### `utils.py`

يحتوي على دوال مساعدة مثل:

- التحقق من حدود الشبكة
- نسخ البيانات
- حساب الحمولة الحالية
- حساب الحمولة القصوى
- دوال مساعدة للبحث والتنسيق

## شكل البيانات المعتمد

### الباقة

كل باقة تُعرّف بثلاثة عناصر:

- نوع الوردة
- اللون
- العدد

مثال:

```python
{"type": "rose", "color": "white", "count": 1}
```

ولأن الروبوت قد يحمل أكثر من باقة من نفس النوع أو اللون، فالأفضل تمثيل الحمولة على شكل **قاموس متداخل** بدل قائمة بسيطة.

---

### الجناح

كل جناح يحتوي على:

- اسم الجناح
- نوع الوردة
- الموقع `(x, y)`
- الاحتياجات المتبقية من الألوان

مثال:

```python
{
    "name": "pavilion1",
    "type": "rose",
    "position": (4, 2),
    "needs": {"red": 2, "white": 1, "pink": 1}
}
```

---

### الروبوت

الروبوت يحتوي على:

- الموقع الحالي
- الحمولة الحالية
- الحد الأقصى للحمولة

مثال:

```python
{
    "position": (3, 1),
    "load": {"rose": {"red": 2, "white": 1}},
    "max_load": 4
}
```

---

### الحالة الكاملة

الحالة الكاملة تمثل الوضع الحالي للبحث، وتضم:

- موقع الروبوت
- موقع المستودع
- الحمولة
- الأجنحة واحتياجاتها المتبقية
- المسار المنفذ حتى الآن
- الكلفة الفعلية `g`

مثال:

```python
{
    "robot_pos": (3, 1),
    "warehouse_pos": (2, 3),
    "load": ...,
    "pavilions": ...,
    "path": [],
    "g": 0
}
```

---

## الحالة الابتدائية

الحالة الابتدائية المعتمدة في المثال هي:

- المستودع في الموقع `(2, 3)`
- الروبوت يبدأ من الموقع `(3, 1)`
- الأجنحة الأربعة:
  - الجناح 1: `(4, 2)` نوعه جوري
  - الجناح 2: `(3, 4)` نوعه توليب
  - الجناح 3: `(5, 4)` نوعه أوركيد
  - الجناح 4: `(2, 5)` نوعه جوليت روز

الاحتياجات تؤخذ كما وردت في نص الوظيفة.
كما أن **الحمولة القصوى** تساوي أكبر مجموع احتياجات جناح واحد، وهي في هذا المثال `4`.

## القواعد الأساسية

### 1) قواعد توليد الحركة

- `move-right`
- `move-left`
- `move-up`
- `move-down`

### 2) قاعدة التحميل

تعمل فقط عندما يكون الروبوت داخل المستودع، وتُطبَّق فقط إذا كانت الحمولة الناتجة قانونية بحسب الشروط المحددة في ورقة الوظيفة.

### 3) قاعدة التفريغ

تعمل فقط عندما يصل الروبوت إلى جناح مناسب، ويمكنه تفريغ الباقات المطابقة لاحتياجات هذا الجناح.

### 4) قواعد المنع

تمنع الحالات التالية:

- الخروج من حدود الشبكة
- تجاوز الحمولة القصوى
- تحميل غير قانوني
- تفريغ غير مناسب

## طريقة التفكير في الحل

المشروع مبني على **قواعد وحقائق**، لذلك كل خطوة في النظام يجب أن تكون نتيجة:

- إضافة Fact
- تعديل Fact
- حذف Fact

هذا يعني أن منطق الحل الأساسي يكون داخل القواعد نفسها، وليس داخل حلقات بحث تقليدية.
